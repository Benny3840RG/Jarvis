Task 7: complete (Claude). `convex/quoteMigration.ts`'s `importLegacyQuote` mutation imports one legacy flat `Quote` (from `src/quotes/quote.ts`'s pre-lifecycle `QuoteStore`, statuses `draft|sent|accepted|declined`) at a time, constructing the target `QuoteAggregate`/`QuoteRevision` directly in its mapped state rather than replaying them through the sequential `draft→reviewed→finalized` transition functions (which don't apply to historical import). Mapping matches the plan's table exactly: `draft` → draft revision, open aggregate; `sent` → finalized revision (fingerprint computed via the existing `convexQuoteRevisionFingerprint`, no fingerprint logic duplicated), open aggregate, no delivery-ledger row invented; `accepted`/`declined` → finalized revision with `historicalOutcome` set, aggregate `commercialStatus` set to match. Finalized imports are stamped `source: "legacy-migration"` — a new optional field added to `QuoteRevision`/the Convex schema/the OpenAPI `QuoteRevisionRecord` schema (additive, `additionalProperties: false` required the OpenAPI addition). Totals are always recomputed from line items via the existing `computeQuoteTotals`, never trusted from the legacy row.

Idempotent replay and rejection reporting are both backed by a new `quoteMigrationRecords` table (`by_owner_and_source_key` index): a repeated `sourceKey` (stably derived as `legacy-quote:<legacy id>` in `src/tools/migrateLegacyQuotes.ts`) returns the exact original result — imported or rejected — without a second write. Rows are rejected (returned, not thrown) for no line items or a colliding quote number; only the deployment guard failing is a hard throw, since that's a systemic misconfiguration rather than a per-row data problem. The guard is layered exactly like `externalReconciliations.cleanup`'s existing repo-wide convention: `src/tools/migrateLegacyQuotes.ts` checks `deployment` starts with `dev:` before doing anything, and `convex/quoteMigration.ts` independently re-checks the exact authorised deployment (`dev:outgoing-ram-798`) — neither on its own is trusted as the only gate. Not exported through HTTP, MCP, tool actions, or any production wiring — `migrateLegacyQuotes` in `src/tools/` is meant for manual, one-off invocation by an operator, matching Task 7's "not exported" requirement; no CLI entrypoint was added since the plan doesn't ask for one and none of the existing smoke-runner entrypoints cover a one-shot migration.

`src/tools/quoteLifecycleSmoke.ts` (`runQuoteLifecycleSmoke`) exercises, end to end against fresh repository instances at each step: create → submitForReview → finalizeRevision → a fresh `getQuote` read confirming the finalized fingerprint survived a repository "restart" → `createRevisionFromFinalized` (fork) → the full delivery ledger lifecycle (createPending → markExecuting → bindProviderReference → markIndeterminate → reconcile) → a final `getQuote` confirming the fork/delivery activity never mutated `commercialStatus` → cleanup of both the quote and its delivery attempts, verified gone.
